# P3 implementation decisions

## D-001 · Keep scientific analysis standard-library only

Use Python's standard library for the deterministic P3 scientific baseline and JSON CLI. The small product-neutral reference host serves the locally bundled React/ECharts module and invokes P3 through the official MCP SDK adapter. P1's shell remains an optional integration target and does not own P3's source semantics or completion. The scientific methods operate on measured points and exact coordinate matches; they do not need image interpolation, model training, a database, or a service framework. MCP protocol behavior is supplied by the pinned official SDK candidate; it does not enter the scientific engine by default. Reopen scientific dependencies only when the frozen challenge suite identifies a concrete capability or performance gap.

The `fab-spatial-map.v2` contract preserves JSON primitive type, modality, missingness, unlabeled defect events, sampling counts, units, geometry, and provenance. The `suite-spatial-map.v1` adapter is a separate explicitly checked compatibility projection and refuses defect events because that contract cannot represent them without ambiguity. P3's standalone rendering uses v2 directly.

## D-002 · Treat the measured-site mask as part of the data

Every numeric fingerprint is computed from supplied observations only. Missing center/edge coverage produces an inconclusive edge-center measure. C02 requires exact matched observed coordinates after the declared rotation unless a single pair uses a declared exact common-site policy with sufficient measured overlap. C05 compares exact sites where available and otherwise uses shared radial/sector profile bins; neither capability interpolates or registers arbitrary transforms. C01 reports robust radial regions and orientation-aware sectors, a least-squares directional plane, and exploratory fixed-grid local-cell clusters where geometry is known. The local-cell threshold is not calibrated. Reticle periodicity stays `NOT_COMPUTED` until reticle geometry and sampling-alias checks exist.

## D-003 · C04 uses a wafer-level max-T rank screen

C04 requires at least 20 earlier, distinct baseline lots and compatible metric, layer, product, population signature, geometry and sampling mask; the target lot is held out. Site robust scores are summarized by a leave-one-wafer-out maximum statistic, preserving the observed within-wafer dependence and controlling the search over sites with a rank p-value. Sites can localize a wafer-level alert but are not individually significant. The finite empirical p-value resolution is reported: 1/21 at 20 baselines and 1/41 at 40. A whole-wafer permutation screen tests global, radial, sector and populated radial-sector profiles for an ordered baseline shift before the alert calculation; detected shifts make C04 `INCONCLUSIVE`. The screen uses 499 shared whole-wafer permutations and alpha 0.01. `NO_SHIFT_DETECTED` is not evidence of stationarity, and the profile screen can miss weaker or unrepresented changes.

The seeded 400-run-per-condition max-T calibration observed null false-alert rates of 6.25% (Gaussian; 95% Wilson interval 4.27%–9.06%), 4.0% (unit-variance t(3)), and 4.0% (skewed lognormal); a predeclared +4 nm synthetic edge shift was detected in 94.25%, 83.0%, and 83.5% of runs. In a separate 200-run pattern study, +4 synthetic shifts were detected in 98.5% (global), 93.0% (center), 88.5% (sector), and 95.5% (edge) cases; a one-site +4 probe was detected in 83.5%, while subtle +1 probes were detected in 19.5% (global) and 12.5% (edge). Baseline profile drift abstention across 200 replicates was 99.0% for a +0.2-per-wafer global trend, 94.0% for the same edge-only trend, and 95.5% for a +2.0 abrupt edge shift in the last 10 of 20 baseline wafers. A +0.1-per-wafer global shift was caught 58.0% of the time and a +0.1 edge trend 28.5%; these weaker changes remain a material limitation. Under 100 null/alternative replicates, 20-wafer and 40-wafer false-alert rates were 3%/8% and +4 edge-shift detection rates were 98%/97%, respectively. These are generated exchangeable populations only. They are not production calibration, company thresholds, a recommended baseline size, or causal evidence. Full raw results are in `release/SCIENTIFIC_PERFORMANCE_BENCHMARK.json`.

## D-004 · C05 ranks multiscale shape without claiming mechanism

C05 combines centered exact-site RMSE with radial-profile and sector-profile distances. Exact values are compared only when observed coordinates match; different sampling masks may use shared radial/sector profile bins only when the minimum of two radial and four sector bins is met. There is no interpolation. It separately reports raw RMSE and mean-level difference, and excludes the target wafer and lot, future records, and incompatible definitions or geometry. The bounded in-memory index stores a validated snapshot, requires explicit invalidation before source updates, and blocks search until a bounded refresh publishes a new generation. The 2026-11-22 synthetic benchmark covers 1,000 maps, five held-out generated pattern regimes, 50 repeated queries, context/time/identity exclusions, alternate sampling, direct/index parity, snapshot mutation, invalidation and refresh. Its predeclared top-5 regime oracle scored 1.00 precision across those five synthetic queries. This is engineering evidence for the generated patterns only; it does not establish retrieval relevance on fab data or blinded engineer agreement.

## D-005 · C02 requires same-wafer temporal evidence

C02 requires same wafer and lot, distinct step instances, increasing timezone-aware measurement times, equal product/metric/definition/unit/layer, matching population metadata, verified orientation, and identical observed coordinate sets after rotation. A pair of maps with different sampling masks may use `exact_common_site_v1` only when the policy was predeclared and both maps meet the configured site-count and coverage minimums. It accepts an ordered series of exact-layout steps, reports signed site deltas and same-direction persistence, records missing repeatability/transform uncertainty, and emits no unobserved values.

## D-006 · C03 uses wafer as the independent unit

C03 pairs the feature and later outcome at the selected map's exact observed die coordinates, applies fixed spatial-block centering within each wafer, then summarizes wafer-level correlations across holdout wafers with an equal-wafer Fisher-z interval. It requires at least 20 holdout wafers from distinct lots and five matched die sites per wafer, including at least two observations in each of two predeclared spatial blocks. The relation, block mapping, time ordering, out-of-time split grouped by both wafer and lot, and complete hypothesis family declared before holdout outcomes must be supplied by the approved quality semantics. If a reported association belongs to a family larger than one, its 95% interval is explicitly per-hypothesis and unadjusted, and the result is labeled exploratory; the engine does not imply family-wise significance. Across 80 generated independent-null studies of 20 candidates each, nominal intervals excluded zero in 4.125% of candidates, while selecting the largest absolute association raised the rate to 50%; all 80 inputs marked post-hoc were refused. This bounded synthetic challenge is not a company threshold. Where the selected map carries recipe, tool, chamber, or route identifiers, the downstream context and rows must match those identifiers. Leave-one-lot-out estimates are exposed as a sensitivity range. It reports association only; product mix, selection and other confounding remain.

## D-007 · Use official SDK transport; company authority remains site-side

The configurable client delegates MCP stdio and Streamable HTTP protocol behavior to the official Python SDK `mcp==2.3.0`; the product contains no custom JSON-RPC transport. Synthetic protocol peers and HTTP fixtures are test-only. The read-only adapter discovers tool descriptors and requires site-provided source grants, exact descriptor hashes, semantic versions, immutable source snapshot versions and registered query-plan approvals before bounded integrated reads. For analysis, source-version equality is checked across approved mapping, semantic response, bounded read and correlated audit. No company endpoint, tool mapping, credential, source grant or real semantics are included. Analysis has no model path. JSON inputs that request `INTERNAL_AUTHORIZED` are refused. The internal preflight consumes a site-generated logical-operation capture using the packaged contract names, lists missing evidence, and always retains `PENDING_INTERNAL`; it cannot authenticate company authority or grant approval.

## D-008 · Compose MCP inputs into the existing C01–C05 engine

`fabintel.mcp_workflow` uses the official-SDK-backed logical adapter and P3 engine. Exact site-approved plans identify the dataset role; server-returned semantic roles map source columns into spatial points and wafer/die observations. Geometry, units, row identity, source scope, truncation, relationship grain, pinned immutable source versions, and remote audit correlation are checked before the engine runs. A test-only protocol peer exercises five bounded reads and all five capabilities with the shared evidence schema; the fixture's five capability results are valid and the envelope is still explicitly synthetic. Missing plan roles remain capability abstentions. No host contract, shell, semantic authority, or company config is added.

## Known work still open

The algorithm thresholds and population assumptions require holdout qualification on representative approved data. Reticle periodicity scores require a traceable alias review and remain exploratory; local-cell clusters are not calibrated for alerting. Arbitrary registration, confound adjustment beyond the predeclared block effect, fab retrieval relevance and engineer agreement, real task-study thresholds, actual company semantic/query-plan approval, target-OS air-gap install, license/rights approval, and signed independent audit remain release gates.
